Build Guide — Telecom Network Intelligence Project (VS Code, start to finish)
This is the consolidated reference. Every function named below was already written and validated earlier in this project's chat history — this guide's job is to tell you exactly which file each one goes into and the order to build and test things in, so you're assembling a known-working system rather than guessing. Where a file is brand-new (not written before), full code is included.

Work through this phase by phase, testing after each phase — don't write all the files first and test at the end. Every earlier bug in this project (stale tables, mismatched joins, silent row-count changes) was caught specifically because each layer was validated before the next was built on top of it. Same discipline applies here.

Phase 1 — simulator/topology.py
Purpose: all static network generation — regions, sites, cells, aggregation nodes, transport mesh, core nodes, and the unified topology table.

Function inventory — search the chat for these exact names and paste them in, in this order:

Order	Function	What it does
1	factor_lookup	Converts qualitative region factors to numeric scores
2	create_regions	Builds the regions table
3	create_sites	Allocates sites to regions
4	assign_site_coordinates	Lat/lon via region anchors + spread (use the widened REGION_ANCHORS/REGION_SPREAD_DEG from the geography-fix round, not the original narrow ones)
5	assign_site_type	urban/suburban/rural classification
6	create_cells	Cell generation per site
7	assign_sector_and_band	Sector cycling + band assignment
8	assign_baseline_heterogeneity	Per-cell quality offset + Watch-band override (from the heterogeneity round)
9	assign_cell_capacity	cell_capacity_mbps from (technology, band)
10	haversine_km	Distance helper — used everywhere below
11	assign_aggregation_nodes + create_aggregation_nodes	K-means-constrained clustering
12	add_region_demand_multiplier + compute_design_load	Demand derivation (the corrected version with demand_variation_factor/watch_utilization_override folded in)
13	assign_aggregation_capacity	Aggregation capacity sizing
14	build_backhaul_links	Site→aggregation links (the version with headroom_factor=1.5, min_capacity_gbps floor)
15	build_transport_mesh	Kruskal MST + redundancy augmentation
16	classify_medium + size_transport_mesh	Mesh link sizing from failover routing (the routed-load version using compute_mesh_failover_load, not the early heuristic)
17	compute_mesh_failover_load	Shortest-path failover load calculation
18	create_core_nodes	Core node placement (off-anchor coordinates)
19	assign_core_dependencies	Primary/secondary core assignment
20	assign_core_capacity	Core capacity from primary+secondary load
21	build_transport_links_table + build_topology_table	Final unified tables
22	validate_topology	Connectivity/failover sanity checks
Constants to paste at the top of the file: NETWORK_CONFIG, REGION_INFO, REGION_ANCHORS (widened version), REGION_SPREAD_DEG (widened version), CORE_ANCHORS.

Test before moving on:

# in a scratch cell or tests/test_topology_smoke.py
import numpy as np
rng = np.random.default_rng(42)
regions = create_regions(REGION_INFO, 50)
sites = create_sites(regions)
sites = assign_site_coordinates(sites, regions, rng=rng)
sites = assign_site_type(sites, regions)
cells = create_cells(regions, sites, rng)
cells = assign_sector_and_band(cells, rng)
cells = assign_baseline_heterogeneity(cells, rng)
cells = assign_cell_capacity(cells)
assert len(sites) == 50 and cells.cell_id.is_unique
print("Phase 1 topology OK:", sites.shape, cells.shape)

Phase 6 — api/schemas.py, dependencies.py, main.py, routers/*
All given in full in the previous message — paste exactly as written. This phase has no dependency on simulator/ at all; it only reads artifacts/.

Test locally:

uvicorn api.main:app --reload
Open http://127.0.0.1:8000/docs — FastAPI's auto-generated Swagger UI. Test each endpoint there directly:

GET /health — confirm status: ok and all artifact flags true.
POST /predict/fault/cell — paste 5+ real hourly rows for one cell from data/hourly/ml_hourly_ran.parquet (pick any cell_id, its last 5-10 rows) as the request body.
POST /predict/fault/cell/explain — same body, confirm top_contributions returns a sensible ranked list (SINR/BLER/PRB features should dominate, not hour_of_day).
POST /predict/congestion?horizon=1h — needs a longer window (up to 336 hourly rows) for full accuracy, but will run with fewer (NaN-tolerant).
POST /predict/anomaly — needs 1-3 recent values for one metric.
If any of these 404s or 422s, check the request body against api/schemas.py's exact field names first — that's the most common mismatch.

Phase 7 — Commit and deploy
git add artifacts/ simulator/ ml_pipeline/ api/ scripts/ requirements.txt render.yaml .gitignore README.md
git commit -m "Full pipeline + FastAPI serving layer"
Push to GitHub, connect the repo to Render, confirm render.yaml's startCommand matches api.main:app. Render will run pip install -r requirements.txt then start uvicorn — it never touches simulator/ or scripts/, only loads artifacts/ at boot, per Phase 6.

Order-of-operations summary (the short version, once everything above is in place)
1. simulator/topology.py        -> test with Phase 1 smoke test
2. simulator/capacity.py        -> audit_capacity_chain on Phase 1 output
3. simulator/operational.py     -> generate 90 days, audit_fault_magnitude
4. ml_pipeline/*.py              -> build feature tables, sanity-check NaNs
5. scripts/run_full_pipeline.py -> python -m scripts.run_full_pipeline (writes artifacts/)
6. api/*.py                      -> uvicorn api.main:app --reload, test via /docs
7. git commit artifacts/ + code -> push -> Render deploy
If something breaks, the failing phase tells you where to look — this is exactly why each phase has its own isolated test above, rather than one big end-to-end run with no checkpoints.
